# 3단계 — 컴포넌트 빌드 (Penpot 저작)

## 입력 (이것만 읽는다)
- `docs/artifacts/01-design-system.md` — 토큰 (JS 상수)
- `docs/artifacts/02-components.md` — 컴포넌트 인벤토리
- **작업 Page 이름 — 인자로 받는다**

## 출력 (이것만 쓴다)
- Penpot **지정된 작업 Page**의 컴포넌트들
- `docs/artifacts/03-built-components.md` — 만들어진 컴포넌트 대장

## 🔴 작업 Page 게이트 (저작 전 필수)
- Page 이름을 **인자로 받는다.** 받지 못했으면 저작을 시작하지 않고 사용자에게 묻는다.
- 기본값으로 첫 Page를 쓰지 않는다. 추측해서 고르지 않는다.
- `중간공유`·`최종제출`은 공용 Page다. 여기서 처음부터 저작하지 않는다.
- `기존파일` Page는 **읽기 전용**이다. 수정 금지.
- Page 전환은 **별도 호출**로 먼저 하고, 다음 호출부터 저작한다.
  `openPage()`는 다음 호출까지 유지되지 않으므로 **모든 스크립트 첫 줄에서 작업 Page를 다시 고정**한다.

## 절차
1. 입력 파일 2개를 읽는다. 없으면 **즉시 중단하고 무엇이 없는지 보고한다.**
2. 01의 `TOKENS` 상수를 저작 코드 상단에 그대로 복사해 두고, 모든 값은 토큰에서 가져온다.
3. 인벤토리의 컴포넌트를 **하나씩** 만든다. 한 번에 몰아 넣지 말고
   **작게 쪼개 실행 → `export_shape`로 PNG 확인 → 수정**을 반복한다.
4. 컴포넌트마다 대장에 이름·id를 기록하고, 전부 끝나면 출력 파일을 쓴다.

## 저작 규칙 (AGENTS.md의 함정 대응 — 어기면 시간을 통째로 날린다)
- **이름·구조는 처음에 확정한다.** 만든 컴포넌트의 이름 변경·자식 remove는 플러그인을 멈춘다.
  잘못 만들었으면 **새 이름으로 새로** 만들고 대장에 폐기 표시를 남긴다.
- 컴포넌트 이름은 파일 전역이다. `{내Page이름}/` 같은 **프리픽스를 붙여** 팀원 것과 충돌을 막고,
  찾을 때는 이름 + **id 프리픽스**로 좁힌다.
- fills는 **penpot 형식** `{fillColor:"#RRGGBB", fillOpacity:1}` — figma 형식을 쓰면 인스턴스 오버라이드가 막힌다.
- 가변 텍스트 칸은 **고정 폭 + 텍스트 정렬** (hug 칸은 텍스트를 갈아끼워도 위치가 안 따라온다).
  단, 고정 폭 텍스트는 `growType = "auto-height"` (fixed면 글자가 잘린다).
- 사이징은 `node.horizontalSizing = "fix"|"auto"` (figma의 `primaryAxisSizingMode`는 안 먹는다).
- 실제 사진이 필요하면 `const img = await penpot.uploadMediaUrl(name, url)` →
  `rect.fills = [{ fillOpacity:1, fillImage: img }]`.

## 출력 형식
```markdown
# 03 — 빌드된 컴포넌트 대장

## Page: {작업 Page 이름}
| 컴포넌트 ID(02 기준) | Penpot 이름 | Penpot id | 오버라이드 방법 (텍스트/색 슬롯별) | 상태 |
|---|---|---|---|---|
| C01 | | | | ✅/폐기 |

## 사용한 토큰 스냅샷
(01의 TOKENS를 그대로 복사 — 4단계가 화면 고유 요소를 그릴 때 쓴다)
```

## 금지
- 입력에 없는 값을 지어내지 않는다. 색·크기·구조의 근거가 01/02에 있어야 한다.
- **특정 PRD 전용 하드코딩 금지.** 심사용 PRD는 미공개다.
- 다른 단계의 출력 파일을 쓰지 않는다. 다른 팀원의 Page를 만지지 않는다.
