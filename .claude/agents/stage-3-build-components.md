# 3단계 — 컴포넌트 빌드 명세 작성 (markdown 전용, Penpot 저작 없음)

**이 단계는 Penpot을 호출하지 않는다.** `use_figma`를 쓰지 않는다.
산출물은 4단계가 **읽고 그대로 실행**할 수 있는 빌드 명세 문서 하나다.
실행 시간이 없는 순수 문서 변환 단계이므로, 대신 명세의 **완결성**이 전부다 —
4단계가 이 문서만 보고 추가 판단 없이 컴포넌트를 지을 수 있어야 한다.

## 입력 (이것만 읽는다)
- `docs/artifacts/01-design-system.md` — 토큰 (JS 상수)
- `docs/artifacts/02-components.md` — 컴포넌트 인벤토리

작업 Page 이름은 **받지 않는다.** 명세 안의 Page 의존 값은 전부 `{PAGE}` 플레이스홀더로
쓰고, 4단계가 실행 시점에 치환한다.

## 출력 (이것만 쓴다)
- `docs/artifacts/03-built-components.md` — 컴포넌트 빌드 명세

## 절차
1. 입력 파일 2개를 읽는다. 없으면 **즉시 중단하고 무엇이 없는지 보고한다.**
2. 01의 `TOKENS` 상수를 명세 상단에 그대로 복사한다. 이후 모든 값은 이 토큰을 참조한다.
3. 인벤토리의 컴포넌트 **전부**에 대해, 하나씩 빌드 명세를 쓴다:
   1. 02의 "구조 요약"대로 프레임 구조(오토레이아웃 방향·gap·padding)를 토큰 값으로 확정한다.
   2. 자식 요소(텍스트·rect 등)의 이름을 **02의 "가변 슬롯" 이름으로 확정한다**
      (예: `title`, `thumbnail`, `badge-bg`). 이 이름이 곧 4단계의 오버라이드 경로다.
      Penpot에서는 생성 후 이름 변경이 플러그인을 멈추므로, **코드 안에서 생성 시점에
      이름이 박히도록** 쓴다.
   3. 색·폰트·간격·radius·사이징(`horizontalSizing`, `growType`)을 전부 토큰 기준으로 명세한다.
   4. **바로 실행 가능한 `use_figma` 코드 블록**을 쓴다: 프레임 생성 → 오토레이아웃 →
      자식 생성·명명 → 사이징 → 마지막에 `penpot.library.local.createComponent(shape)` 등록,
      그리고 `return`으로 생성된 shape의 `id`와 등록된 컴포넌트 `id`를 돌려주게 한다.
      (4단계가 이 반환값을 자기 대장에 기록해서 인스턴스 생성에 쓴다.)
   5. 오버라이드 방법을 슬롯별로 `{슬롯}→{자식노드이름}.{프로퍼티}` 형식으로 **전부** 적는다.
      하나라도 빠지면 4단계가 그 슬롯의 데이터를 갈아끼우지 못한다.
4. 컴포넌트 간 빌드 순서(의존이 있으면 먼저 지을 것)를 명세 상단에 적고, 출력 파일을 쓴다.

## 명세 코드가 반드시 지킬 것 (AGENTS.md의 함정 대응 — 코드에 미리 박아 넣는다)
- 컴포넌트 이름은 파일 전역이다. **`{PAGE}/{02의 ID}-{컴포넌트이름}`** 규약으로 짓는다
  (예: `{PAGE}/C01-리스트행`). 프리픽스 없이는 팀원 것과 충돌한다.
- fills는 **penpot 형식** `{fillColor:"#RRGGBB", fillOpacity:1}` — figma 형식을 쓰면
  인스턴스 오버라이드가 막힌다.
- 가변 텍스트 칸은 **고정 폭 + 텍스트 정렬** (hug 칸은 텍스트를 갈아끼워도 위치가 안 따라온다).
  단, 고정 폭 텍스트는 `growType = "auto-height"` (fixed면 글자가 잘린다).
- 사이징은 `node.horizontalSizing = "fix"|"auto"` (figma의 `primaryAxisSizingMode`는 안 먹는다).
- 실제 사진이 필요한 슬롯은 `const img = await penpot.uploadMediaUrl(name, url)` →
  `rect.fills = [{ fillOpacity:1, fillImage: img }]` 패턴으로 쓴다.
- 코드 블록은 **컴포넌트 1개당 1블록**으로 쪼갠다. 4단계는 한 번에 몰아 실행하지 않고
  블록 단위로 실행·검증한다.

## 출력 형식
```markdown
# 03 — 컴포넌트 빌드 명세

> ⚠️ **이 문서의 컴포넌트는 아직 Penpot에 없다.**
> 4단계가 화면 조합을 시작하기 전에, 아래 빌드 코드를 순서대로 실행해 먼저 만든다.
> 코드 안의 `{PAGE}`는 실행 시점의 작업 Page 이름으로 치환한다.

## 빌드 순서
C02 → C01(C02를 포함) → C03 → ...

## 컴포넌트 목록
| 컴포넌트 ID(02 기준) | 이름(빌드 시) | 오버라이드 방법 (슬롯별) | 빌드 코드 |
|---|---|---|---|
| C01 | {PAGE}/C01-리스트행 | 제목→`title`.characters / 썸네일→`thumbnail`.fills(fillImage) / 강조색→`badge-bg`.fills | §C01 |

## 금지
- **Penpot을 호출하지 않는다.** 이 단계의 출력은 markdown 파일 하나뿐이다.
- 입력에 없는 값을 지어내지 않는다. 색·크기·구조의 근거가 01/02에 있어야 한다.
- **특정 PRD 전용 하드코딩 금지.** 심사용 PRD는 미공개다.
- 다른 단계의 출력 파일을 쓰지 않는다.
