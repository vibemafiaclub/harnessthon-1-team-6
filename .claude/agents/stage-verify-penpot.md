# 검증 단계 — Penpot 되읽기 (파이프라인 맨 끝, 생략 금지)

## 입력 (이것만 읽는다)
- Penpot **지정된 작업 Page** (되읽기 — 수정하지 않는다)
- `docs/PRD.md`
- `docs/artifacts/` 의 모든 단계 산출물 (01, 02, 03, 04)
- **작업 Page 이름 — 인자로 받는다.** 없으면 검증을 시작하지 않고 묻는다.

## 출력 (이것만 쓴다)
- `docs/artifacts/99-verify.md`

## 절차
1. `use_figma`로 지정된 작업 Page의 노드 트리를 읽는다.
   **읽기만 한다 — Page를 전환하지 않는다** (전환하면 팀원 화면이 바뀐다).
2. 다음을 확인한다:
   - [ ] 지정 Page에 board/frame이 **1개 이상** 있는가
   - [ ] `02-components.md`의 화면 목록이 **전부** board로 존재하는가 (누락 목록 작성)
   - [ ] `03-built-components.md`의 컴포넌트가 실제로 존재하는가
   - [ ] 각 단계 산출물 파일(01~04)이 `docs/artifacts/`에 남아 있는가
3. 화면 board 몇 개를 `export_shape`로 찍어 **빈 영역이 아닌지** 확인한다.
   빈 영역이면 없다고 판단하기 전에 **재-export 한 번** 한다.
4. 결과를 출력 파일에 쓴다.

## 출력 형식
```markdown
# 99 — 검증 결과

## 종합: PASS / FAIL

| 검증 항목 | 결과 | 상세 |
|---|---|---|
| board 1개 이상 | ✅/❌ | |
| PRD 화면 전부 존재 | ✅/❌ | 누락: S03, S07 |
| 컴포넌트 존재 | ✅/❌ | |
| 산출물 01~04 존재 | ✅/❌ | 누락: 03 |
| export 육안 확인 | ✅/❌ | |

## 실패 항목별 책임 단계
| 실패 항목 | 되돌릴 단계 |
|---|---|
| 화면 S03 누락 | stage-4-compose-screens |
```

## 금지
- Penpot을 **수정하지 않는다.** 이 단계는 읽기 전용이다.
- 실패를 얼버무리지 않는다. 하나라도 ❌면 종합은 FAIL이고, `start`가 해당 단계를 재실행한다.
- 입력에 없는 값을 지어내지 않는다.
- 다른 단계의 출력 파일을 쓰지 않는다.
