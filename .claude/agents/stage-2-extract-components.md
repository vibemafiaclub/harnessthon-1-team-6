# 2단계 — 화면·컴포넌트 추출

## 입력 (이것만 읽는다)

- `docs/PRD.md`

## 출력 (이것만 쓴다)

- `docs/artifacts/02-components.md`

## 절차

1. `docs/PRD.md`를 읽는다. 없으면 **즉시 중단하고 무엇이 없는지 보고한다.**
2. **PRD의 문장을 화면 목록으로 환원한다.** "최소 2개"는 하한선일 뿐이다. 특히:
   - 유저 스토리에 "…그 결과를 확인하고 싶다" → **결과 화면** 추가
   - "상세로 넘어가는 진입점"이 필수 요소 → 그 **목적지 화면** 추가
   - "정렬/필터 진입점" → 눌렀을 때 뜨는 **시트/모달** 추가
   - 4절(사용자 상황)의 빈 상태·로딩·실패 → 각각 **화면(또는 상태 변형) 하나씩**
   - 각 화면마다 **근거가 된 PRD 문장을 인용**해 남긴다. 근거 없는 화면은 넣지 않는다.
3. 화면들을 가로지르며 **반복 등장하는 UI 단위를 컴포넌트로 추출**한다.
   아래 **승격 규칙**으로 판정한다 — 감으로 정하지 않는다.

   | 판정                | 조건                                                            |
   | ------------------- | --------------------------------------------------------------- |
   | **컴포넌트로 승격** | 서로 다른 화면 2곳 이상에 등장한다                              |
   | **컴포넌트로 승격** | 한 화면 안에서 **데이터만 바뀌며 3회 이상** 반복된다            |
   | **variant로 흡수**  | 구조·자식 개수가 같고 **색/텍스트/아이콘만** 다르다             |
   | **별도 컴포넌트**   | 자식의 **개수나 배치 자체가** 다르다 (variant로 만들면 깨진다)  |
   | **승격 안 함**      | 한 화면에서 1회만 쓰이고 다른 화면에 안 나온다 → 화면 고유 요소 |

4. 누락 방지를 위해 아래 **범용 분류 체계**를 전부 훑는다.
   각 칸에 대해 "이 PRD에 해당하는 것이 있는가?"를 묻고, 없으면 `해당 없음`이라고 적는다.
   (칸을 비워두면 빠뜨린 것인지 없는 것인지 구분되지 않는다.)

   | 분류         | 훑을 대상                                                          |
   | ------------ | ------------------------------------------------------------------ |
   | Chrome       | 상태바 · 상단바(타이틀형/뒤로가기형) · 하단 탭바 · 홈 인디케이터   |
   | Navigation   | 탭/세그먼트 · 필터·정렬 진입점 · 칩 그룹 · 페이지네이션·인디케이터 |
   | Collection   | 리스트 행 · 카드 · 그리드 셀 · 가로 스크롤 레일 · 섹션 헤더        |
   | Data display | 뱃지·태그 · 아바타 · 수치/지표 · 게이지·차트 · 메타 라인           |
   | Action       | 버튼(주/보조/파괴) · 아이콘 버튼 · FAB · 하단 고정 액션바          |
   | Input        | 텍스트 입력 · 선택(칩/라디오/체크) · 토글 · 스테퍼 · 업로더        |
   | Overlay      | 시트 · 모달 · 스크림 · 토스트                                      |
   | Feedback     | 빈 상태 · 스켈레톤/로딩 · 에러·재시도 · 진행 표시                  |

5. 각 컴포넌트에 **명세 필드를 전부 채운다.** 빈칸은 3단계에서 저작자가 지어내게 만든다.
   - `variant 축` — 축 이름과 값 목록 (예: `state: default|selected`). 없으면 `단일`
   - `슬롯` — 저작 후 인스턴스에서 갈아끼울 것. **타입(텍스트/이미지/색/반복개수)까지** 명시
   - `사이징` — 각 자식의 `fix | auto | fill`. 특히 아래 두 경우는 반드시 지정한다
     - **가변 텍스트가 들어가는 칸은 `fix`(고정 폭) + 텍스트 정렬** — hug면 값이 바뀔 때 위치가 어긋난다
     - **화면 하단에 고정되는 요소는 높이를 숫자로 명시** — 남는 공간을 늘어나게 두면 되돌아간다
   - `토큰` — 1단계 산출물의 토큰 이름으로만 적는다. 원시 hex·px를 쓰지 않는다
6. 화면 × 컴포넌트 매핑 표를 만들고 출력 파일을 쓴다.
   매핑 표를 다 채운 뒤, **어떤 화면에서도 참조되지 않는 컴포넌트**가 있으면 지운다.

## 출력 형식

```markdown
# 02 — 화면·컴포넌트 명세

## 화면 목록

| ID  | 화면 이름 | 유형(기본/시트/모달/상태변형) | 근거 (PRD 문장 인용) |
| --- | --------- | ----------------------------- | -------------------- |
| S01 |           |                               |                      |

## 컴포넌트 인벤토리

분류별로 훑은 결과. 해당 없는 분류는 `해당 없음`이라고 남긴다.

| ID  | 컴포넌트 이름 | 분류 | 구조 요약 (자식·방향·gap·padding) | variant 축 | 슬롯 (이름:타입) | 사이징 | 토큰 | 승격 근거 |
| --- | ------------- | ---- | --------------------------------- | ---------- | ---------------- | ------ | ---- | --------- |
| C01 |               |      |                                   |            |                  |        |      |           |

- `승격 근거`는 위 승격 규칙의 어느 조건에 걸렸는지 (`2화면` / `3회반복`)와 그 위치를 적는다.
- `사이징`은 고정 폭이 필요한 자식과 높이를 못 박아야 하는 자식을 반드시 포함한다.

## 화면 × 컴포넌트 매핑

| 화면 ID | 사용하는 컴포넌트 ID | 인스턴스 수 | 화면 고유 요소 (컴포넌트가 아닌 것) |
| ------- | -------------------- | ----------- | ----------------------------------- |

## 상태 변형 계획

원본을 다시 짓지 않고 **복제 후 덮어쓸 것만** 적는다.

| 원본 화면 ID | 변형 (빈/로딩/에러/모달) | clone 후 바꿀 것 |
| ------------ | ------------------------ | ---------------- |

## 3단계 인계 메모

| 항목                           | 내용                                            |
| ------------------------------ | ----------------------------------------------- |
| 저작 순서 (의존성 낮은 것부터) |                                                 |
| 이름 확정 목록                 | 저작 후 이름 변경이 불가하므로 여기서 못 박는다 |
| 1단계에 없어 새로 필요한 토큰  | 없으면 `없음`                                   |
```

## 금지

- 입력에 없는 값을 지어내지 않는다. 모든 화면·컴포넌트는 PRD 문장이 근거여야 한다.
- **특정 PRD 전용 하드코딩 금지.** 심사용 PRD는 미공개다.
  "당근"·"에어비앤비" 같은 고유명사나 고정된 화면 개수를 이 지침에 박지 않는다.
  (출력물에는 당연히 해당 PRD의 화면 이름이 들어간다 — 금지 대상은 **이 지침 파일**이다.)
- Penpot을 호출하지 않는다. 이 단계는 문서만 만든다.
- 다른 단계의 출력 파일을 쓰지 않는다.
