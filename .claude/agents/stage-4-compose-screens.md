# 4단계 — 컴포넌트 빌드 + 화면 조합 (Penpot 저작)

## 입력 (이것만 읽는다)
- `docs/artifacts/02-components.md` — 화면 목록·매핑·상태 변형 계획
- `docs/artifacts/03-built-components.md` — 컴포넌트 **빌드 명세** (코드 블록·오버라이드 방법·토큰).
  **이 문서의 컴포넌트는 아직 Penpot에 없다** — 아래 절차 A에서 이 단계가 직접 만든다.
- **작업 Page 이름 — 인자로 받는다**

## 출력 (이것만 쓴다)
- Penpot **지정된 작업 Page**의 화면 board들
- `docs/artifacts/04-screens.md` — 만들어진 화면 대장

## 🔴 작업 Page 게이트 (저작 전 필수)
- Page 이름을 **인자로 받는다.** 받지 못했으면 저작을 시작하지 않고 사용자에게 묻는다.
- 기본값으로 첫 Page를 쓰지 않는다. `중간공유`·`최종제출`에서 처음부터 저작하지 않는다.
- `기존파일` Page는 읽기 전용. 수정 금지.
- Page 전환은 별도 호출로 먼저. **모든 스크립트 첫 줄에서 작업 Page를 다시 고정**한다.

## 절차

### A. 컴포넌트 빌드 (화면 조합 전 필수 — 03 명세를 그대로 실행)
1. 입력 파일 2개를 읽는다. 없으면 **즉시 중단하고 무엇이 없는지 보고한다.**
2. 03의 "빌드 순서"대로, 컴포넌트별 빌드 코드 블록을 **1블록 = 1회 실행**으로 돌린다.
   - 코드 안의 `{PAGE}`를 작업 Page 이름으로 치환한 뒤 실행한다.
   - 각 블록의 반환값(`shapeId`, `componentId`)을 **빌드 대장에 즉시 기록**한다.
     이 id가 아래 B에서 인스턴스를 만드는 유일한 참조다.
   - 블록이 실패하면 같은 이름으로 재시도하지 않는다 — 03의 함정 규칙대로
     **새 이름으로 새로** 만들고 대장에 폐기 표시를 남긴다.
3. 전부 등록되면 컴포넌트들을 `export_shape`로 **한 번에 훑어** 확인한다.
   (컴포넌트마다 개별 확인 루프를 돌지 않는다 — 세부 확인은 화면 단위 루프에서 한다.)

### B. 화면 조합
4. 02의 **화면 목록 전부**를 대상으로 한다. 하나라도 빼면 검증 단계에서 반려된다.
5. 화면마다 **저작 전 복잡도를 판단**한다.
   - 상태 변형 3개 이하 + 컴포넌트 인스턴스 수가 적음 → 바로 저작 진행.
   - 상태 변형 4개 이상, 또는 롱스크롤처럼 큰 화면 → board 구조(사용할 컴포넌트·상태 변형 목록)를
     먼저 요약해 사용자에게 보여주고 **승인받은 뒤** 저작한다. 컴포넌트 이름·구조는 한번 만들면
     되돌리기 위험하므로(AGENTS.md 함정), 큰 화면일수록 진행 전 확인이 시간을 아낀다.
6. 화면마다: board 생성 → **생성 직후 바로 부모(작업 Page root 또는 상위 board)에 `appendChild`** →
   매핑된 컴포넌트를 **인스턴스로** 배치 → 화면 고유 요소는 03의 토큰 스냅샷으로 직접 저작.
   - 인스턴스의 원본 컴포넌트는 **A에서 기록한 `componentId`로 찾는다.**
   - 데이터가 다른 행은 **인스턴스 재사용 + 오버라이드**로 처리한다. 오버라이드는 03 명세의
     "오버라이드 방법" 열에 적힌 `{슬롯}→{자식노드이름}.{프로퍼티}` 경로를 그대로 따른다
     (예: `제목→title.characters`, `썸네일→thumbnail.fills(fillImage)`).
     이 경로에 없는 슬롯은 임의로 처리하지 않고 누락으로 보고한다.
   - 색 오버라이드는 penpot 형식 fills로 한다.
7. 상태 변형(빈/로딩/에러/모달)은 **처음부터 다시 짓지 말고 `shape.clone()`** → 덮을 것만 얹는다.
8. 화면 하나 끝날 때마다 **`export_shape`로 PNG 확인 → 수정** 루프를 돈다. 안 보고 쌓지 않는다.
   **같은 화면에 대해 최대 2회까지만** 수정·재확인한다. 그래도 어긋나면 원인을 "미저작/보류" 표에
   남기고 다음 화면으로 넘어간다 — 무한히 export만 반복하지 않는다.
9. 마무리 일괄 처리:
   - `growType==="auto-height"` 텍스트를 전부 `resize`로 재계산시킨다 (hHug 안 텍스트 아래 잘림 방지).
   - 자식 순서가 어긋났으면 `board.insertChild(index, node)`로 고친다.
10. 출력 파일을 쓴다 (빌드 대장 포함).

## 저작 규칙 (AGENTS.md의 함정 대응)
- 반투명 스크림은 렌더링에서 사라질 수 있다 → 스크림을 덮지 말고 **뒤 화면 board의 `opacity`를 낮춘다**.
- `layoutGrow` Spacer는 폭 1로 되돌아간다 → 하단 고정 요소는 Spacer 높이를 **계산해서 명시**.
- 비-오토레이아웃 board는 `appendChild`가 자식을 안 옮긴다 → 붙인 뒤 `c.x = parent.x + dx; c.y = parent.y + dy`.
- 컴포넌트는 **A에서 기록한 빌드 대장의 id로 `findShapeById`를 직접 사용**해 찾는다. 이름 매칭은
  보조 확인용으로만 쓴다 — 이름만으로 찾으면 옆 팀원의 동명 컴포넌트가 조용히 잡힌다.
- 만든 컴포넌트의 **이름 변경·자식 remove는 플러그인을 멈춘다.** 이름·구조는 03 명세의
  생성 코드에서 확정된 그대로 두고, 잘못 만들었으면 새 이름으로 새로 만든다.
- **board는 만든 직후 반드시 부모에 `appendChild`한다.** 페이지 트리에 안 붙은 board는
  `export_shape`가 실패한다(빈 화면이 아니라 에러로 실패).
- `export_shape`가 빈 영역이면 없다고 판단하기 전에 **재-export 한 번**.

## 출력 형식
```markdown
# 04 — 저작된 화면 대장

## Page: {작업 Page 이름}

## 빌드된 컴포넌트 대장 (절차 A의 결과)
| 컴포넌트 ID(03 기준) | Penpot 이름 | shapeId | componentId | 상태 |
|---|---|---|---|---|
| C01 | 이태경/C01-리스트행 | (id) | (id) | ✅/폐기 |

## 화면 대장
| 화면 ID(02 기준) | board 이름 | board id | 사용 인스턴스 | export 확인 |
|---|---|---|---|---|
| S01 | | | C01×3, C04 | ✅ |

## 미저작/보류 화면
| 화면 ID | 사유 |
|---|---|
```

## 금지
- 입력에 없는 값을 지어내지 않는다. 화면 구성의 근거가 02/03에 있어야 한다.
- 02에 있는 화면을 임의로 생략하지 않는다. 못 만들었으면 "미저작" 표에 사유와 함께 남긴다.
- **특정 PRD 전용 하드코딩 금지.** 심사용 PRD는 미공개다.
- 다른 단계의 출력 파일을 쓰지 않는다. 다른 팀원의 Page를 만지지 않는다.
