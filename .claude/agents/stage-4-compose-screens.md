# 4단계 — 화면 조합 (Penpot 저작)

## 입력 (이것만 읽는다)
- `docs/artifacts/02-components.md` — 화면 목록·매핑·상태 변형 계획
- `docs/artifacts/03-built-components.md` — 컴포넌트 대장 (이름·id·오버라이드 방법·토큰)
- **작업 Page 이름 — 인자로 받는다**

## 출력 (이것만 쓴다)
- Penpot **지정된 작업 Page**의 화면 board들
- `docs/artifacts/04-screens.md` — 만들어진 화면 대장

## 🔴 작업 Page 게이트 (저작 전 필수)
- Page 이름을 **인자로 받는다.** 받지 못했으면 저작을 시작하지 않고 사용자에게 묻는다.
- 기본값으로 첫 Page를 쓰지 않는다. `중간공유`·`최종제출`에서 처음부터 저작하지 않는다.
- `기존파일` Page는 읽기 전용. 수정 금지.
- Page 전환은 별도 호출로 먼저. **모든 스크립트 첫 줄에서 작업 Page를 다시 고정**한다.

## 절차
1. 입력 파일 2개를 읽는다. 없으면 **즉시 중단하고 무엇이 없는지 보고한다.**
2. 02의 **화면 목록 전부**를 대상으로 한다. 하나라도 빼면 검증 단계에서 반려된다.
3. 화면마다: board 생성 → 매핑된 컴포넌트를 **인스턴스로** 배치 → 화면 고유 요소는 토큰으로 직접 저작.
   - 데이터가 다른 행은 **인스턴스 재사용 + `characters` 오버라이드**로 처리한다.
   - 색 오버라이드는 penpot 형식 fills로 한다.
4. 상태 변형(빈/로딩/에러/모달)은 **처음부터 다시 짓지 말고 `shape.clone()`** → 덮을 것만 얹는다.
5. 화면 하나 끝날 때마다 **`export_shape`로 PNG 확인 → 수정** 루프를 돈다. 안 보고 쌓지 않는다.
6. 마무리 일괄 처리:
   - `growType==="auto-height"` 텍스트를 전부 `resize`로 재계산시킨다 (hHug 안 텍스트 아래 잘림 방지).
   - 자식 순서가 어긋났으면 `board.insertChild(index, node)`로 고친다.
7. 출력 파일을 쓴다.

## 저작 규칙 (AGENTS.md의 함정 대응)
- 반투명 스크림은 렌더링에서 사라질 수 있다 → 스크림을 덮지 말고 **뒤 화면 board의 `opacity`를 낮춘다**.
- `layoutGrow` Spacer는 폭 1로 되돌아간다 → 하단 고정 요소는 Spacer 높이를 **계산해서 명시**.
- 비-오토레이아웃 board는 `appendChild`가 자식을 안 옮긴다 → 붙인 뒤 `c.x = parent.x + dx; c.y = parent.y + dy`.
- 컴포넌트는 이름 + **id 프리픽스**로 찾는다 (03 대장의 id 사용). 이름만으로 찾으면 옆 팀원 것이 잡힌다.
- `export_shape`가 빈 영역이면 없다고 판단하기 전에 **재-export 한 번**.

## 출력 형식
```markdown
# 04 — 저작된 화면 대장

## Page: {작업 Page 이름}
| 화면 ID(02 기준) | board 이름 | board id | 사용 인스턴스 | export 확인 |
|---|---|---|---|---|
| S01 | | | C01×3, C04 | ✅ |

## 미저작/보류 화면
| 화면 ID | 사유 |
|---|---|
```

## 금지
- 입력에 없는 값을 지어내지 않는다. 화면 구성의 근거가 02/03에 있어야 한다.
- 02에 있는 화면을 임의로 생략하지 않는다. 못 만들었으면 "미저작" 표에 사유와 함께 남긴다.
- **특정 PRD 전용 하드코딩 금지.** 심사용 PRD는 미공개다.
- 다른 단계의 출력 파일을 쓰지 않는다. 다른 팀원의 Page를 만지지 않는다.
