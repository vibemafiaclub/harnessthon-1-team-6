# 1단계 — 디자인 시스템 추출

## 입력 (이것만 읽는다)
- Penpot 파일 `작업`의 **`기존파일` Page** — 레퍼런스 디자인. **읽기 전용, 수정 금지**
- `docs/PRD.md` — 서비스의 톤·도메인 파악용 (보조)
- 웹 (WebSearch/WebFetch) — PRD가 언급하는 기존 서비스의 **공개 브랜드 자료** (보조. 없으면 생략 가능)

## 출력 (이것만 쓴다)
- `docs/artifacts/01-design-system.md` — 시각 토큰·패턴 (3단계가 소비)
- `docs/artifacts/01-voice.md` — 보이스·카피 규칙 (4단계가 화면 텍스트를 쓸 때 소비)

## 절차
1. `high_level_overview` 툴로 Penpot 사용법을 먼저 확인한다.
2. `use_figma`로 `penpot.currentFile.pages`를 순회해 `기존파일` Page를 찾는다.
   - **Page를 전환(openPage)하지 않는다.** 읽기만 할 때 전환하면 팀원이 보는 화면이 바뀐다.
   - 노드 트리를 순회하며 색(fills)·타이포(fontFamily, fontSize, fontWeight)·간격(gap, padding)·모서리(borderRadius)를 수집한다.
   - 텍스트 노드의 `characters`도 전부 수집한다 — 이것이 **카피 코퍼스**다.
     (어미·어휘·문장 길이·숫자 표기 방식을 뒤의 보이스 규칙 도출에 쓴다)
3. 수집한 값을 **빈도·역할 기준으로 정리**해 토큰으로 명명한다 (예: `primary`, `textSecondary`, `spacingMd`).
4. `penpot.fonts.all`로 레퍼런스의 폰트가 서버에 있는지 확인한다.
   **없으면 조용히 대체되므로**, 서버에 실재하는 대체 폰트를 여기서 확정해 기록한다.
5. **브랜드 식별**: PRD에서 이 서비스를 만드는 팀/기존 서비스의 이름을 추출한다.
   (예: PRD 1절의 "OO을 만든 팀" 표현. 이름은 PRD에서 런타임에 읽는다 — 지침에 박지 않는다)
6. **웹 조사**: 추출한 브랜드명으로 검색한다.
   - 쿼리 템플릿: `"<브랜드> 브랜드 보이스"` / `"<브랜드> UX 라이팅"` / `"<브랜드> 리브랜딩 디자인 원칙"` / `"<브랜드> 디자인 시스템"`
   - 소스 우선순위: **공식 블로그·채용 블로그·디자인 시스템 문서 > 2차 분석글**. 출처 URL을 반드시 기록한다.
   - 수집 대상: 브랜드 핵심 가치, 페르소나 형용사, 말투에 대한 언급, 서체·컬러의 **의도**(무엇을 표현하려 했는가)
   - 검색 결과가 없거나 빈약하면 **이 단계를 건너뛴다.** 웹 조사는 보강이지 필수 입력이 아니다.
7. **교차 검증으로 보이스 규칙 확정**: 웹에서 온 원칙은 **가설**, 2단계 카피 코퍼스는 **증거**다.
   - 카피 코퍼스에서 확인되는 가설만 규칙으로 승격한다 (출처 태그: `양쪽 일치`)
   - 코퍼스에서만 관찰된 규칙도 채택한다 (출처 태그: `파일 관찰`)
   - 웹에만 있고 코퍼스로 확인 안 되는 것은 규칙이 아니라 **참고**로만 남긴다 (출처 태그: `웹`)
   - 웹 조사를 건너뛴 경우 코퍼스 단독으로 규칙을 만든다 — 이 폴백이 있어야 어떤 PRD에서도 돌아간다.
8. 출력 파일 **2개**를 쓴다. `01-voice.md`는 웹 조사를 건너뛴 경우에도
   **카피 코퍼스 단독 규칙으로 반드시 쓴다** — 4단계가 이 파일의 존재를 전제한다.

## 출력 형식
다음 단계(3·4단계)가 코드에 그대로 붙여 쓸 수 있는 **JS 상수 객체**를 중심으로 적는다.
(`figma.variables.*`는 토큰이 남지 않으므로 쓰지 않는다 — JS 상수가 공식 토큰 저장소다.)

```markdown
# 01 — 디자인 시스템

## 토큰 (JS 상수 — 저작 코드에 그대로 복사해서 사용)
```js
const TOKENS = {
  color: { primary: "#______", bg: "#______", text: "#______", textSecondary: "#______", border: "#______", danger: "#______" },
  font:  { family: "______" /* penpot.fonts.all 로 존재 확인된 이름 */, h1: 24, h2: 18, body: 15, caption: 12 },
  space: { xs: 4, sm: 8, md: 16, lg: 24 },
  radius:{ sm: 4, md: 8, lg: 16 },
};
```

## 출력 형식 — `01-voice.md`

```markdown
# 01 — 보이스 & 카피 규칙

> 이 문서는 **4단계(화면 조합)가 화면의 모든 텍스트(레이블·더미 데이터·상태 문구)를
> 쓸 때 읽는다.** 시각 토큰은 여기 없다 — `01-design-system.md`를 볼 것.

## VOICE (JS 상수 — 더미 텍스트·레이블 작성 시 그대로 따른다)
```js
const VOICE = {
  brandEssence: "______",              // 웹 조사 결과. 없으면 카피 코퍼스에서 귀납
  persona: ["______", "______"],       // 브랜드 페르소나 형용사 2~4개
  어미: "______",                       // 예: "~해요체" — 반드시 카피 코퍼스로 검증된 값
  버튼레이블: "______",                  // 예: "동사형 2~4어절"
  숫자표기: "______",                    // 예: "숫자에는 해석 문장을 붙인다"
  금지표현: ["______"],                  // 예: "명령형", "전문용어 단독", "과장·긴박 표현"

## 규칙별 근거
| 규칙 | 출처 (`양쪽 일치` / `파일 관찰` / `웹`) | 근거 (카피 예시 또는 URL) |
|---|---|---|

## 조사 출처
- (URL 목록. 웹 조사를 건너뛰었으면 "해당 없음 — 파일 코퍼스 단독"이라고 쓴다)
```

## 금지
- `기존파일` Page 수정 금지. Page 전환도 하지 않는다 (읽기는 전환 없이 가능하다).
- 입력에 없는 값을 지어내지 않는다. **시각 토큰 값(색·크기·간격)은 레퍼런스에서
  실제로 관찰된 값이어야 한다.** VOICE의 브랜드 철학 항목은 출처 URL 또는
  카피 코퍼스 예시가 붙어야 한다 — 근거 없는 항목은 쓰지 않는다.
- 웹 조사 실패를 실행 실패로 취급하지 않는다. 조사가 안 되면 파일 코퍼스 폴백으로 진행한다.
- **특정 PRD 전용 하드코딩 금지.** 심사용 PRD는 미공개다.
  "당근"·"에어비앤비" 같은 고유명사나 고정된 화면 개수를 지침에 박지 않는다.
- 다른 단계의 출력 파일을 쓰지 않는다.
