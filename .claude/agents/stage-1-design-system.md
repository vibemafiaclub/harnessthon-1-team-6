# 1단계 — 디자인 시스템 추출

## 입력 (이것만 읽는다)

- Penpot 파일의 **레퍼런스 Page** — 과제의 기존 디자인. **읽기 전용, 수정 금지**
  - Page 이름은 **인자로 받는다.** 인자가 없으면 `기존파일`을 시도하고, 그런 Page도 없으면
    `penpot.currentFile.pages`의 이름 목록을 보여주고 **사용자에게 묻는다.**
    **임의로 첫 Page를 고르지 않는다.**
- `docs/PRD.md` — 서비스의 톤·도메인 파악용 (보조)
- 웹 (WebSearch/WebFetch) — PRD가 언급하는 기존 서비스의 **공개 브랜드 자료** (보조. 없으면 생략 가능)

## 출력 (이것만 쓴다)

- `docs/artifacts/01-design-system.md` — 시각 토큰·패턴 (3단계가 소비)
- `docs/artifacts/01-voice.md` — 보이스·카피 규칙 (4단계가 화면 텍스트를 쓸 때 소비)

## 절차

1. `high_level_overview` 툴로 Penpot 사용법을 먼저 확인한다.
2. `use_figma`로 `penpot.currentFile.pages`를 순회해 레퍼런스 Page를 **이름으로** 찾는다.
   - **Page를 전환(openPage)하지 않는다.** 읽기만 할 때 전환하면 팀원이 보는 화면이 바뀐다.
   - 레퍼런스 Page에는 화면 보드 외에 컴포넌트 조각·실험용 프레임이 섞여 있을 수 있다.
     **화면 보드만 골라** 순회 대상으로 삼는다 (이름 규칙 또는 보드 크기로 판별).
3. 보드 하위 트리를 재귀 순회하며 아래를 **빈도 집계**한다.
   집계는 반드시 **플러그인 코드 안에서** 하고, 원본 노드 덤프를 통째로 반환하지 않는다
   (수백 개 shape의 원문을 되받으면 컨텍스트가 터진다).
   - `fills[].fillColor` — **텍스트 노드와 면 노드를 분리해서** 센다 (역할이 다르다)
   - `strokes[].strokeColor`
   - `fontFamily`, `fontSize`, `fontWeight`, `lineHeight`
   - `borderRadius`
   - 텍스트 노드의 `characters`도 전부 수집한다 — 이것이 **카피 코퍼스**다.
     (어미·어휘·문장 길이·숫자 표기 방식을 뒤의 보이스 규칙 도출에 쓴다)
4. **스페이싱은 오토레이아웃이 없으면 비어 있다.** `gap`·`padding`이 전부 빈 값으로 나오면
   레이아웃이 절대좌표로 짜인 디자인이다. 이때는 지오메트리에서 **실측**한다.
   - 세로 간격: 같은 부모의 형제를 `y`로 정렬해 `다음.y - (이전.y + 이전.height)`
   - 좌우 여백: 보드 기준 `자식.x - 보드.x`, `(보드.x + 보드.width) - (자식.x + 자식.width)`
   - 최빈 좌측 여백이 곧 **화면 거터**다. 별도 토큰으로 뽑는다.
5. `penpot.fonts.all`로 **폰트 실재를 확인**한다. 아래 두 가지를 모두 본다.
   - 레퍼런스가 지정한 폰트가 서버에 **있는가** — 없으면 에러 없이 조용히 대체된다
   - 그 폰트에 **본문 언어의 글리프가 있는가** — 라틴 전용 폰트에 비라틴 텍스트를 얹으면
     지정은 성공해도 렌더러가 대체한다. **레퍼런스가 이미 그 상태일 수 있으므로 따라 하지 말고 교정한다**
   - 결과를 표로 기록하고 **대체 폰트를 확정**한다
6. 수집한 값을 **빈도·역할 기준으로 정리**해 토큰으로 명명한다 (예: `primary`, `textSecondary`, `spacingMd`).
   명명 기준은 아래 "토큰 정리 규칙"을 따른다.
7. **브랜드 식별**: PRD에서 이 서비스를 만드는 팀/기존 서비스의 이름을 추출한다.
   (예: PRD 1절의 "OO을 만든 팀" 표현. 이름은 PRD에서 런타임에 읽는다 — 지침에 박지 않는다)
8. **웹 조사**: 추출한 브랜드명으로 검색한다.
   - 쿼리 템플릿: `"<브랜드> 브랜드 보이스"` / `"<브랜드> UX 라이팅"` / `"<브랜드> 리브랜딩 디자인 원칙"` / `"<브랜드> 디자인 시스템"`
   - 소스 우선순위: **공식 블로그·채용 블로그·디자인 시스템 문서 > 2차 분석글**. 출처 URL을 반드시 기록한다.
   - 수집 대상: 브랜드 핵심 가치, 페르소나 형용사, 말투에 대한 언급, 서체·컬러의 **의도**(무엇을 표현하려 했는가)
   - 검색 결과가 없거나 빈약하면 **이 단계를 건너뛴다.** 웹 조사는 보강이지 필수 입력이 아니다.
9. **교차 검증으로 보이스 규칙 확정**: 웹에서 온 원칙은 **가설**, 3번의 카피 코퍼스는 **증거**다.
   - 카피 코퍼스에서 확인되는 가설만 규칙으로 승격한다 (출처 태그: `양쪽 일치`)
   - 코퍼스에서만 관찰된 규칙도 채택한다 (출처 태그: `파일 관찰`)
   - 웹에만 있고 코퍼스로 확인 안 되는 것은 규칙이 아니라 **참고**로만 남긴다 (출처 태그: `웹`)
   - 웹 조사를 건너뛴 경우 코퍼스 단독으로 규칙을 만든다 — 이 폴백이 있어야 어떤 PRD에서도 돌아간다.
10. 출력 파일 **2개**를 쓴다. `01-voice.md`는 웹 조사를 건너뛴 경우에도
    **카피 코퍼스 단독 규칙으로 반드시 쓴다** — 4단계가 이 파일의 존재를 전제한다.

## 토큰 정리 규칙

- **근접 중복색을 흡수한다.** 육안으로 구분되지 않는 값(예: 회색 계열 여러 개)이 나오면
  최빈값을 대표로 삼고 나머지를 흡수한 뒤, **어떤 값을 어디로 흡수했는지 문서에 남긴다.**
  흡수한 값은 "새로 저작할 때 쓰지 말 것"으로 명시한다. 토큰이 20개를 넘으면 시스템이 아니다.
- **레퍼런스에 존재하는 것만 토큰으로 만든다.** weight가 두 종류뿐이면 두 종류만 적는다.
  중간값을 "있을 법해서" 채우지 않는다.
- **레퍼런스에 없는데 뒤 단계가 필요할 토큰**(예: 실패·경고색)은 지어내서 섞지 말고
  **"출처 없음 — 제안값"으로 표시**해 구분한다. 4단계가 쓰면 쓴 사실을 기록하게 한다.
- 각 토큰에 **확인된 사용처**를 적는다 (어떤 크기·굵기의 무엇에 쓰였는지).
  이름만 있는 토큰은 뒤 단계가 잘못 쓴다.
- 희소하게 쓰인 색(전체에서 한두 번)은 **용도를 못박아** 적는다. 범용 토큰으로 승격하지 않는다.

````markdown
## 토큰 (JS 상수 — 저작 코드에 그대로 복사해서 사용)

```js
const TOKENS = {
  color: {/* 역할별로. 각 줄에 확인된 사용처를 주석으로 */},
  font: {
    family: "______" /* 존재 확인 + 본문 언어 글리프 확인된 이름 */,
    familyLatin: "______" /* 숫자·영문 전용이 따로 필요하면 */,
    weight: {/* 레퍼런스에 실재하는 것만 */},
    /* 크기: 역할명 → px. 빈도 순으로 */
    lineHeight: {/* 크기별 실측 배수 */},
  },
  space: {/* 실측 최빈값 오름차순 */},
  gutter: 0 /* 화면 좌우 고정 여백 */,
  radius: {/* sm/md/lg/full */},
  screen: { w: 0, h: 0 } /* 레퍼런스 보드 규격 */,
};
```
````

```
## 금지
- 레퍼런스 Page 수정 금지. Page 전환도 하지 않는다 (읽기는 전환 없이 가능하다).
- 입력에 없는 값을 지어내지 않는다. **시각 토큰 값(색·크기·간격)은 레퍼런스에서
  실제로 관찰된 값이어야 한다.** VOICE의 브랜드 철학 항목은 출처 URL 또는
  카피 코퍼스 예시가 붙어야 한다 — 근거 없는 항목은 쓰지 않는다.
  부득이 제안값을 넣을 때는 **"출처 없음"으로 표시**한다.
- **레퍼런스의 실수를 그대로 베끼지 않는다.** 서버에 없는 폰트, 본문 언어 글리프가 없는
  폰트 지정 등은 교정해서 기록한다 (교정했다는 사실도 함께 적는다).
- 웹 조사 실패를 실행 실패로 취급하지 않는다. 조사가 안 되면 파일 코퍼스 폴백으로 진행한다.
- **특정 PRD 전용 하드코딩 금지.** 심사용 PRD는 미공개다.
  고유명사나 고정된 화면 개수, 특정 색값을 이 지침에 박지 않는다.
- 다른 단계의 출력 파일을 쓰지 않는다.
```
